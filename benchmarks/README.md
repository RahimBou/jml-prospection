# Benchmark JML — leads Casaran 2026-10\n\nCe dossier contient un banc de test séparé du moteur de production.\n\n## Source\n\n`leads-casaran-2026-10.csv` est une extraction minimale des 200 observations du PDF `leads_casaran.pdf` fourni pour le test.\n\nLe jeu conserve uniquement les champs utiles au benchmark : date, type, source, emplacement, prix demandé, statut, surface, nature de l'emplacement et prix demandé au m².\n\nLes noms et téléphones des prospects ne sont pas nécessaires au test et ne sont pas recopiés dans le dataset.\n\n## Ce que le benchmark mesure\n\n1. **Géocodage** : la commune/quartier peut-il être résolu ?\n2. **Rapprochement adresse** : seules les observations contenant une rue/numéro sont envoyées à `/api/prospect-match`.\n3. **DVF/DPE** : statut de rapprochement retourné par le moteur.\n4. **Comparables** : nombre et médiane €/m² retournés par l'Estimateur local.\n5. **Positionnement** : valeur de marché indicative = médiane €/m² × surface annoncée, puis écart au prix demandé.\n\n### Règle importante\n\nLe prix Leboncoin/portail est un **prix demandé**, pas un prix de vente.\n\nUn écart au prix demandé ne doit donc pas être présenté comme une « erreur de l'Estimateur ». Pour mesurer une vraie précision, il faut rapprocher le bien avec une mutation DVF réelle suffisamment fiable.\n\nLes terrains, garages, parkings, commerces et immeubles atypiques doivent être analysés séparément : le moteur de comparables maison/appartement ne doit pas être évalué sur eux comme s'il s'agissait de logements standards.\n\n## Exécution\n\nDepuis la racine du projet :\n\n    node scripts/benchmark-leads.js --base-url http://localhost:10000 --out /tmp/jml-benchmark.json\n\nOu contre Render :\n\n    node scripts/benchmark-leads.js --base-url https://jml-prospection-web.onrender.com --out /tmp/jml-benchmark.json\n\nLe script est **lecture seule** : il n'écrit rien dans le CRM.\n\n## Interprétation\n\n- `geocodeRate` : capacité de résolution territoriale.\n- `exactAddressRowsTested` : nombre d'observations permettant réellement de tester le rapprochement adresse à partir du PDF.\n- `dvfExact` / `dvfStreet` : solidité du rapprochement transactionnel.\n- `dpeConfirmed` : nombre de rapprochements DPE confirmés.\n- `comparableRows` : nombre de lignes où l'Estimateur a produit une médiane exploitable.\n- `askingVsMarketBenchmarkBands` : positionnement du prix demandé par rapport au benchmark €/m².\n\nLes 200 lignes sont des **observations de leads**, pas nécessairement 200 biens uniques : certaines annonces sont répétées à plusieurs dates/sources. Ces répétitions sont utiles pour tester la veille et l'historique de prix, mais ne doivent pas être comptées comme 200 biens indépendants pour une mesure de précision statistique.\n
